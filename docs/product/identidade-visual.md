# Identidade Visual — Site Pessoal Marcos Ranauro

## Objetivo

Definir a direção visual do site pessoal de Marcos Ranauro para orientar layout, cores, tipografia, componentes, animações e estilo geral da interface.

---

## Direção visual aprovada

A direção visual do projeto será:

> Premium editorial tech com interatividade futurista controlada.

A base será uma mistura de:

- black & white tech editorial;
- futurista / tech interativo.

A proporção visual recomendada é:

- 70% editorial premium;
- 30% futurista tech.

O site deve parecer premium primeiro e tecnológico depois.

---

## Sensação desejada

O site deve transmitir:

- profissionalismo;
- tecnologia;
- maturidade técnica;
- elegância;
- confiança;
- clareza;
- personalidade;
- atenção aos detalhes.

O visitante deve perceber que Marcos Ranauro é um desenvolvedor fullstack com visão técnica, visual e profissional.

---

## O que evitar

Evitar:

- visual gamer;
- neon exagerado;
- excesso de partículas;
- animações pesadas;
- template genérico de programador;
- aparência infantil;
- excesso de efeitos futuristas;
- poluição visual;
- fonte difícil de ler;
- layout muito carregado.

---

| Bordas sutis | `#242B3A` |
| Texto principal | `#F5F7FA` |
| Texto secundário | `#A8B0C2` |
| Texto discreto | `#6F7A8F` |

### Cores de destaque

| Uso | Cor |
|---|---|
| Azul tecnológico | `#38BDF8` |
| Ciano suave | `#22D3EE` |
| Roxo discreto | `#8B5CF6` |

As cores de destaque devem ser usadas com moderação em botões, hovers, bordas ativas, pequenos glows e detalhes visuais.

---

## Tipografia

A tipografia deve ser moderna, limpa e forte.

Sugestões:

- títulos: `Sora`, `Space Grotesk`, `Geist` ou `Inter`;
- texto comum: `Inter` ou `Geist`;
- detalhes técnicos: `JetBrains Mono` ou `Geist Mono`.

Regras:

- títulos com presença;
- parágrafos curtos;
- boa legibilidade;
- evitar fonte futurista demais;
- evitar blocos longos de texto.

---

## Layout

O layout deve ter:

- bastante respiro visual;
- seções bem separadas;
- grid sutil;
- cards alinhados;
- poucos elementos competindo por atenção;
- limite de largura no desktop;
- boa adaptação mobile.

Sugestão:

- container entre `1120px` e `1280px`;
- espaçamento vertical generoso;
- padding confortável no mobile.

---

## Hero

O hero deve comunicar rapidamente:

- quem é Marcos Ranauro;
- o que ele faz;
- qual valor entrega;
- como entrar em contato ou ver projetos.

Elementos recomendados:

- nome;
- título: Fullstack Developer;
- frase de posicionamento;
- CTA principal: Ver projetos;
- CTA secundário: Entrar em contato;
- links para GitHub e LinkedIn;
- elemento visual tecnológico sutil.

Evitar no hero:

- texto demais;
- avatar genérico;
- ilustração artificial;
- excesso de partículas;
- neon forte;
- frase clichê.

---

## Cards

Os cards devem ter aparência premium e tecnológica.

Características:

- fundo escuro levemente elevado;
- borda sutil;
- cantos arredondados;
- hover elegante;
- sombra discreta;
- boa hierarquia visual.

Hover permitido:

- leve elevação;
- borda mais clara;
- glow sutil;
- transição suave.

---

## Botões

### Botão principal

Deve ter mais destaque visual.

Pode usar:

- fundo claro;
- azul/ciano discreto;
- hover com brilho leve;
- texto bem legível.

### Botão secundário

Deve ser mais discreto.

Pode usar:

- fundo transparente;
- borda sutil;
- texto claro;
- hover suave.

---

## Animações

As animações devem ser elegantes e leves.

Permitido:

- fade-in;
- slide-up discreto;
- hover em cards;
- transições suaves;
- glow leve;
- movimento sutil no hero.

Evitar:

- animações longas;
- elementos piscando;
- movimento constante;
- parallax pesado;
- efeitos que atrapalhem leitura;
- animações exageradas no mobile.

---

## Elementos futuristas permitidos

Permitido usar com moderação:

- grid sutil no fundo;
- linhas finas;
- glow discreto;
- blur radial;
- bordas com luz leve;
- microinterações;
- elementos abstratos no hero.

A camada futurista deve ser percebida, não gritar.

---

## Responsividade

O site deve funcionar muito bem em mobile.

No mobile:

- textos legíveis;
- botões fáceis de tocar;
- cards sem estourar largura;
- animações reduzidas;
- navbar simples;
- hero objetivo;
- espaçamento confortável.

---

## Critérios de aceite visual

A identidade visual será considerada bem aplicada se:

- [ ] O site parecer premium e tecnológico.
- [ ] A estética editorial for mais forte que a futurista.
- [ ] O hero tiver clareza e impacto.
- [ ] Os cards forem consistentes.
- [ ] Os botões tiverem hierarquia clara.
- [ ] O site funcionar bem em mobile.
- [ ] Não houver excesso de neon.
- [ ] Não parecer gamer.
- [ ] Não parecer template pronto.
- [ ] As animações forem suaves.
- [ ] A tipografia for legível.
- [ ] A paleta estiver consistente.

---

## Regra para Claude Code

Ao implementar a interface, seguir esta direção visual sem inventar outro estilo.

A IA não deve mudar a identidade visual sem registrar decisão em `DECISOES.md`.

Ao finalizar implementação visual relevante, atualizar `CONTEXT.md`.
